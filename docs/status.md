# Collector plan status

Implementation follows C1–C5 for the standalone `~/signals` project, under Apache-2.0. This remains version 0.1.0 with a provisional Signals wire contract. No 1.0 release or official SDK conformance is claimed.

| Area | Implemented and verified | Remaining gate / deliberate difference |
|---|---|---|
| C1 ingest/storage | Generated typify types + raw schema validation, committed SQLx metadata, key/caller caches, bulk caller upsert, binary COPY retry/row fallback, network hash + UA family, skew, partitioning, replay safety, admin API CLI. 300,000 events/60 s, 2-CPU collector, p99 10.87 ms; interrupted DB recovery/replay preserved acknowledged rows. | Official Plan 1 schema, batch mapping, verbatim ingest OpenAPI and upstream conformance require the unavailable spec. Development fixtures pass and import/provenance tooling is ready. |
| C2 read/aggregation | EventStore trait; received-time commit barrier and worker exclusion; SQL aggregation/histograms; batched retention; daily caller reads/history; every overview delta, p99/top tools; arbitrary retained boundaries; UTC/dense charts; paginated events/sessions/timeline. Literal “index-only every dashboard query” is not a safe blanket requirement for unbounded JSON/unique sets; heap-backed indexed queries are identified honestly. Historical partial buckets outside raw retention require aligned ranges. |
| C3 UI/auth | Seven styled light/dark/mobile views, tool activity/latency and recent errors, caller history, unlimited timeline pages, configured Setup URL, local users/keys/settings. | C5 release/docs | Apache-2.0, root CI for generation/SQL/schema fixtures/property/browser/Docker/fault checks, prepared amd64/arm64 GHCR + static musl binary + npm workflow, embedded docs site, upgrade/maintenance/alert docs, Node/Python MCP 2026-07-28 examples. | GitHub/npm publishing is intentionally unconfigured. No public artifacts, 1.0 tag, or external developer quickstart approval yet. Stable release gate requires official spec provenance/conformance and publishing metadata. |

Raw retention keeps the partial UTC day internally (at most one additional day) to preserve daily rollup convergence. User-facing raw reads and ingest timestamp validation enforce the configured rolling retention. The default policy remains 30 days; summaries remain 400 days.

See [validation](validation.md) and [acceptance evidence](acceptance-evidence.md) for commands and measurement limits. Official spec integration and external/public release gates cannot be completed without their inputs; the implementation does not substitute an invented SDK contract.
